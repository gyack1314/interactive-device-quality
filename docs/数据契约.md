# 原始资料契约

所有资料均为本地合成。JSONL一行一条来源观察，row_id仅标识该观察；同业务ID可以在不同revision、批次或接收位置出现。未写revision的静态目录按文件给定值解释，不隐含线上查询。事实字段中的None为缺少来源值，不是零或否。

金额字段以minor结尾时为该币种最小单位整数；数量、位置、时间的单位以字段后缀和政策说明为准。日期为ISO日期；绝对时刻携带偏移；原始received字段决定可见性，不能仅按发生日期提前使用资料。后续业务修改以相同格式输入，不限定样本编号。

## 业务政策

### denominator

症状风险主分母为capture_complete且duration_seconds>0的可见体验会话，不是设备数；同会话同症状无论告警数最多计一次。另报每设备、每小时风险时需明确不同分母，不能混用。

### state

状态区间[start_day,end_day)，repairs在维修日开始替代旧部件/固件；整机ID不变。维修日及之后评估新组合，之前仍属旧组合。

### comparison_family

```json
{
  "reference_batch": "B0",
  "batches": [
    "B1",
    "B2"
  ],
  "symptoms": [
    "freeze"
  ],
  "family_alpha": 0.05,
  "minimum_sessions": 20
}
```

### estimation

业务要求分场地和强度校正的效应及不确定区间，允许解释合理的方法；标明环境事件的排除/保留敏感性，争议环境事件不能当确认事实。完全混杂时不得声称可分离因果；不是要求统计显著的预定结论。

### retest

每设备每分析日最多一项；既有待执行任务不能重复；必须有同意，技能分钟不超容量，优先级需要依据风险与可确认性公开解释。回执仅改变处置状态，不撤销历史会话；不把复测通过者作为所有维修设备的效果样本。

## 资料检查

`python -m unittest discover -s tests -v`只检查资料字节与格式，不是尚未开发业务功能的验收。manifest.json中的摘要对应提交内原始字节，收到后续批次应独立登记来历，不修改旧原始记录。
